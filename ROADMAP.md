# Roadmap

Where the engine is going. These are intentions, not dated commitments. The [features page](docs/features.md) shows where each part stands today, with the lines still to come marked *(Coming soon)*, and every release lists what changed.

## Next, in the parts you can use today

- **Compare Figma and code:** how components move and what they draw beyond their colours, such as shadows and blurs; and each product page checked against its Figma screen.
- **Test accessibility:** your designed screens checked in Figma for contrast and target size, before any code.
- **Catch drift in product code and AI edits:** faults in a component's own code that show only when a screen uses it; and what the system lacks sent to Figma as to-do cards, after a yes.
- **Build with AI, on the system:** the same rules in the instruction files of Cursor, Copilot and other agents; and prototypes built with real components.
- **Fit your team's setup:** answers for agents with no terminal, such as prototyping tools, through MCP.

## Then, the parts coming soon

- **Update Figma from the code:** accessibility notes, screen issues and links to the code written into Figma, after a yes.
- **Keep products on the system:** token renames and retired components carried to every product, with a ready-made fix each.
- **Generate components in Figma and code:** new and changed components built from a plain description, with your own styles and structure, in Figma, in code or both, as you choose.
- **Build code from Figma:** the build order for a system that exists only in Figma, each piece checked once built.

## The project itself

- A second maintainer with admin access, for continuity and reviewed changes ([GOVERNANCE.md](GOVERNANCE.md)).
- The OpenSSF Best Practices silver level.

## Suggest something

Open an issue with what you need and why. Requests that come with a real case (a workflow, a check that would have caught something) are the easiest to act on.
