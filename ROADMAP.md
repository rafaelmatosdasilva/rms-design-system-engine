# Roadmap

Where the engine is going. These are intentions, not dated commitments. The [features page](docs/features.md) shows where each part stands today, with the lines still to come marked *(Coming soon)*, and every release lists what changed.

## Next, in the parts you can use today

- **Lint your codebase:** faults in a component's own code that show only when a screen uses it; what the system lacks sent to Figma as to-do cards, after a yes; and token renames and retired components carried to every product, with a ready-made fix each.
- **Compare Figma and code:** how components move and what they draw beyond their colours, such as shadows and blurs; and each product page checked against its Figma screen.
- **Test accessibility:** your designed screens checked in Figma for contrast and target size, before any code.
- **Works with your tools:** answers for agents with no terminal, such as prototyping tools, through MCP.

## Then, the parts coming soon

- **Annotate Figma from the code:** accessibility notes, screen issues and links to the code written into Figma, after a yes.
- **Turn Figma into code:** the build order for a system that exists only in Figma, each piece checked once built.
- **Bring code components into Figma:** a component that exists only in code drawn in Figma, with its props and tokens, for designers to fine-tune.
- **Generate components in Figma and code:** new and changed components built from a plain description, with your own styles and structure, in Figma, in code or both, as you choose.
- **Prototype with your real components:** prototypes built with your real components, and the same rules in the instruction files of Cursor, Copilot and other agents.

## The project itself

- A second maintainer with admin access, for continuity and reviewed changes ([GOVERNANCE.md](GOVERNANCE.md)).
- The OpenSSF Best Practices silver level.
